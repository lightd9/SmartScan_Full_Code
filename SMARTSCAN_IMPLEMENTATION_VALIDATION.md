# First improvement package: implementation and validation

7 November 2026. Scope: M0 verification corrections, the initial M1 shared evidence service, and native Android/iOS project preparation. The full roadmap is not complete.

## Implemented

- Correct consumer V2 lifecycle mappings, including delivered versus sold and recalls after sale. Previously saved stage-4 results carrying the old recall label render as sold.
- Preserve issued identifier case; validate explicit QR contract addresses before extracting the serial; reject partial/malformed identifiers.
- Distinguish authoritative absence, registry-only fallback and unavailable verification. Registry metadata cannot override a fresh chain lifecycle, and fallback does not invent a live verification time.
- `POST /v1/assessments` uses an event ID for scan recording; `GET /v1/assessments/:serialNumber` reads without inserting a scan. The existing `/scan-events` endpoint remains compatible. Old clients without an event ID cannot receive retry deduplication guarantees.
- Shared backend findings cover registry identity, available custody consistency/recall checks and existing frequency/geography flags. Packing, production feed, seller comparison and purchase-location evidence remain explicitly unknown. No numerical authenticity score is generated.
- Consumer and web display backend findings and evidence coverage. Saved mobile results show their check time. On monitoring failure, the response preserves chain evidence and marks monitoring unavailable.
- Scan migration 014 adds event ID, request digest and purpose. Transaction locks protect simultaneous retries and per-subject counting; a reused ID with a different payload is rejected. Coordinates retain the existing rounded, unverified treatment. Consumer GPS/purchase context is not collected in this package.
- Backend CORS configuration supports explicitly listed native origins. Native Android/iOS projects exist for both mobile apps; enterprise still uses the visibly labelled demo service.
